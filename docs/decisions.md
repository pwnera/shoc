# shoc decision log

Decisions made while designing and building shoc (September 2026). D1–D17 come from the design; D18 onwards were forced by the implementation, and each one is a bug or a gap we hit. Each one stands until an RFC in `rfcs/` replaces it. Format: decision · why · consequence.

| # | Decision | Why | Consequence |
| --- | --- | --- | --- |
| D1 | Target companies of 20–500 people with no security team | Underserved: MDR/SIEM priced for bigger teams; OSS SIEMs need analysts | Defaults, docs and sources focus on AWS, Okta/Entra, Google/M365, GitHub, EDR APIs |
| D2 | Full SOC scope run by agents 24/7 (monitoring, triage, IR, CTI, hunting, detection engineering, MCO, reporting), humans as escalation | Users asked for a full SOC, not just an analyst assistant | 10 crew roles; humans approve L2 actions and handle escalations |
| D3 | OSS project first; managed SaaS later on AWS with Databricks SQL Serverless | Build trust and adoption before revenue | Tenant ID everywhere from day one; no control-plane code in the OSS repo |
| D4 | Composable event store: Postgres, Databricks SQL, Snowflake | Small users need cheap Postgres; larger ones already own a warehouse | Canonical SQL over OCSF + SQLGlot; `EventStore` adapter + conformance suite; no warehouse-specific features in core |
| D5 | Headless, AI-first: one capability registry generates REST, MCP, CLI, Slack and agent tools | Users want to drive it from their AI assistants and Slack, not another dashboard | No required UI; the console under `console/` is an optional client |
| D6 | Minimal dependencies: one image + Postgres, ≤ 8 core Python packages | Easy self-hosting, small attack surface, less to maintain | Postgres replaces queue, workflow engine, scheduler, graph and memory stores; see the "instead of" table in `architecture.md` |
| D7 | Agent interaction via openspaces (blackboard), memory and attack rehearsal | Debate + evidence improves verdicts; rehearsal predicts attack paths | `openspace_messages` table, Challenger role, world graph + memory tables, weekly rehearsal on a read-only snapshot |
| D8 | Bounded autonomy L0/L1/L2; L2 approval only by a human principal (over MCP, confirmed by that human: D65) | Trust: one bad automatic action costs more than any missing feature | Typed playbook steps, YAML policy, reversible L1 only, dry-run default for new installs |
| D9 | Evidence or nothing: verdicts must cite event IDs | Reduce hallucinated verdicts; make answers auditable | Uncited verdicts downgraded to "needs human"; citations validated in evals |
| D10 | Python 3.12 single package | SQLGlot and the MCP SDK are Python; one language for kernel and content tooling | Node only at build time for the optional console |
| D11 | Own agent loop, own Sigma-subset compiler, two thin LLM clients | Avoid framework lock-in and heavy deps | We maintain a few hundred lines each; LLM providers: Anthropic + any OpenAI-compatible endpoint (covers Databricks model serving, vLLM, Ollama) |
| D12 | Apache 2.0 + DCO, no CLA (confirmed 2026-10-07 before the repository went public; AGPL was considered) | Easy adoption by companies and partners, low contributor friction | Can't relicense contributions later; SaaS must add operations, never remove OSS features |
| D13 | Public promise: no feature moves from OSS to paid | Trust with the community | Open-core boundary table in `prd.md` |
| D14 | Monorepo, trunk-based, Conventional Commits, release-please, SemVer, 6–8 week minors | Predictable, automated releases | Public contract frozen at v0.4, stable at v1.0 |
| D15 | Signed supply chain: PyPI Trusted Publishing, cosign-signed multi-arch images, provenance, SBOM, OpenSSF Scorecard ≥ 8 | A security product must have a secure supply chain | Release pipeline in `prd.md`; actions pinned by SHA |
| D16 | The optional console is a dense shadcn layout, shipped in `console/` as a client of the public API | A fast UI for teams that want one, without a second way in | See `ui-prototype.md`; never required by the kernel |
| D17 | The name is "shoc", short for Security Headless Operation Center | It says what the product is: a SOC with no screen required | Package, CLI, Postgres schema, `SHOC_*` environment variables, Helm chart and `x-shoc-*` headers all use `shoc`; trademark check still open |
| D18 | Rules only match the products their `logsource` names | A GitHub rule matching `secret` fired on CloudTrail's `GetSecretValue` | The compiler adds a `metadata_product` filter from `logsource`; a product shoc cannot map is not filtered, and `tests/unit/test_compiler.py` requires every shipped rule to map |
| D19 | Cases group findings by the typed entities they share, not by one entity string | Five findings about the same stolen key were becoming two cases because some keyed on the key and some on the user | Findings carry `entities` (`key:…`, `user:…`, `ip:…`); `shoc.case_entities` plus union-find joins them, and an open case that already covers any of those entities absorbs new findings |
| D20 | An explicit `--lookback` overrides the rule watermark | `shoc detect run --lookback 1h` silently skipped everything the last scheduled cycle had already passed, which made replays look broken | Scheduled cycles still resume from the watermark, capped at four of the rule's own windows |
| D21 | Row-level security keyed on a `shoc.tenant_id` session setting, applied per capability call | Tenant isolation should survive a query inside a capability that forgets its `WHERE` clause | A session that never sets the variable (psql, `shoc migrate`, backups) is unrestricted, and `shoc migrate` warns when connected as a superuser, because superusers bypass policies entirely |
| D22 | Agents read through a separate read-only Postgres role | "Agents read, the runner acts" should be enforced by the database, not only by the registry | `shoc grant-readonly` creates it; `SHOC_READONLY_DSN` switches agent principals onto it; without it the guarantee is the registry's alone |
| D23 | Slack approvers are an explicit allow-list of user IDs | Being in a channel is not authority, and an approval must come from a named person | `slack.configure` takes `approvers`; anyone else gets read-only tools and a refusal message |
| D24 | The public contract is snapshotted in `contract/v1.json` and checked in CI | "Frozen at v0.4" needs a mechanism, not a promise | Capabilities cannot lose a field, gain a required one, rename a surface or loosen autonomy without a deliberate commit that updates the snapshot |
| D25 | An agent's citations are verified against the event store before they count | A model that invents event IDs would otherwise produce a confident, uncheckable verdict | Invented IDs are dropped; a claim with none left is refused and downgraded to an observation, and the case verdict becomes `needs_human` |
| D26 | The policy refuses to load if an L1 action is not reversible | "L1 is reversible" was a comment; now it is a constraint | `Policy.validate` raises at load, so a bad policy fails `shoc plan` rather than at 3am |
| D27 | The Tuner writes diffs and has no write access to `content/` | A model that can edit detections can disable them | Proposals live in `shoc.rule_proposals` with a unified diff; a human merges them in git |
| D28 | A scripted LLM client ships with the code, not just the tests | Crew plumbing (rounds, budgets, citations, downgrades) must be testable without model variance | `ScriptedClient` is part of `shoc/agents/llm.py`; `evals/` measures the model, the test suite measures the machinery |
| D29 | Five crew roles use a model; five do not | CTI, Hunter, Tuner, Ops and Reporter work on data we already have (feeds, rule health, spend, the graph) so a model would add cost and variance without adding judgement | Sentinel, Investigator, Challenger, IR Commander and Orchestrator call an LLM; the other five are deterministic and run with `SHOC_LLM_PROVIDER=none`. `architecture.md` §5 describes all ten as agents; this is how they are built |
| D30 | Attack rehearsal is a deterministic coverage engine, not an adversary agent loop | `architecture.md` §4 describes adversary personas taking turns with a model. What a small team needs from a rehearsal is "would we have seen this?", and rule-to-technique coverage answers that exactly, reproducibly and for free | Personas are YAML (technique, stage, the products that would show it); the engine marks each step covered, blind or uncovered against the rules and the sources actually connected. A model can narrate the result later; it cannot change it |
| D31 | Capabilities are L0 or L2; L1 belongs to actions | An L1 *call* means nothing: autonomy is about what happens in the world, not about reading a table | `Capability.autonomy` is L0 or L2 (enforced in `tests/unit/test_security_invariants.py`); L1 lives in the autonomy policy, on the action |
| D32 | CTI is deterministic except for reading a report (amends D29) | Feeds, matching, retro-hunts and `intel.lookup` are lookups and arithmetic. Reading prose is not: a threat report names actors, describes techniques and publishes indicators in sentences | The CTI role gains a prompt and a schema, and is the sixth role that uses a model. `intel.digest` is the only CTI operation that requires one; everything else still works with `SHOC_LLM_PROVIDER=none` |
| D33 | `intel.digest` is model-driven, and its indicators are quarantined rather than trusted | The maintainers chose the model producing the indicator list over regex extraction with model narration. That choice is injectable (a report can ask for an indicator to be planted) so the cost is paid in storage, not in hope | Report text reaches the model only inside `safety.quote()`; indicators land under `report:<host>` at confidence 0.35–0.55, below every automatic-action floor; a value not present in the report text is stored `unverified`; `report_uid` makes a bad report's indicators removable in one statement |
| D34 | An indicator is never sent to a third party if it is internal | Researching 10.0.0.5 or `fileserver.internal` discloses the shape of a customer's network to VirusTotal and friends, and learns nothing | `osint.is_internal` is checked before any outbound call; internal values get the local sources only, and the answer says so. Every source also declares the hosts it may call, so a value taken from a log cannot steer a lookup |
| D35 | A blocking action is researched and peer-reviewed before it runs automatically (RSP-5, RSP-6) | `waf.block_ip` was L1. Nothing asked whether the address was a Cloudflare edge, an AWS NAT range or the office VPN, and blocking one of those takes the company offline automatically, at 3am, which is the failure this project exists to prevent | `research_before_action` and `review_before_action` on an action rule. Any gate failing (no research, shared infrastructure, known egress, an inconclusive verdict, an objection, an unreachable reviewer, no model) downgrades L1 to L2. A gate can only ever make an action harder; it never raises autonomy and never approves an L2 |
| D36 | The case room is renamed the openspace, and agents may speak in it without being scheduled (RFC 0010) | The round order made every agent's knowledge reachable only by whoever the script called next, so the Investigator inferred what an address was to the company and CTI never heard the cases its reports were about | `shoc.openspace_messages` with a `to_agent` column and three kinds: `request`, `answer`, `interject`. Who is interested is a word-boundary match over terms each role declares, so no model decides routing; two requests and one interruption per round, six peer turns per case, checked against the existing budget |
| D37 | The operator is absent: nothing may rest on a human arriving (RFC 0011) | The company running shoc has one technical person who does not open it most days. An L2 action sat `proposed` for ever, a `needs_human` case sat in `analysis` for ever, and the crew ran once per case and was never sent back, so a real L1 containment action was proposed, allowed by the policy, and never performed | A proposal waiting for an approval has a four-hour deadline: past it a `high` or `critical` case pages once, and anything lower is rejected with the reason written into the case. A `needs_human` case is told nobody is coming and the crew goes back to it. `shoc/cases/unattended.py` never approves anything and never raises an action's autonomy |
| D38 | The crew's proposals go to the policy, and the worker runs what it approves | The IR Commander's proposals were openspace messages: no `shoc.actions` row existed, nothing executed `approved` actions outside a playbook run, and the verdict was recorded after the Commander spoke so every L1 proposal was judged against `confidence = 0.0` and downgraded | `actions.from_crew` proposes each one, the disposition is recorded before the Commander is asked, and `worker.run_approved_actions` queues every approved action with no `run_uid`, which also covers an L2 a human approved in Slack. The Commander is shown the action catalogue, because it was naming actions that do not exist |
| D39 | Agents call read capabilities while they are thinking (RFC 0011) | `build_dossier` assembled everything an agent would ever see before the discussion started, so nobody could widen a window, check whether an address appeared last month, or ask what else an account touched. An analyst who cannot pivot is commenting on a sample | Tool use in `shoc/agents/llm.py` for both providers; `shoc/agents/tools.py` derives tools from the registry and executes them through `Capability.invoke`, so principal, scope, autonomy and audit are unchanged. A role's caller holds exactly the scopes of the capabilities it was offered, all of them reads. Results are quoted as untrusted data and what was looked up is recorded on the message |
| D40 | A specialist is called by the evidence, not by a keyword (RFC 0011) | CTI had no scheduled turn: it could only interrupt, a round allowed one interruption, and `roles.interested` ranked by declaration order with CTI last and Challenger's terms including "benign" and "expected". A case about a hash, a command line or a technique contains none of CTI's words, so it was silent on every case | `shoc/agents/observables.py` reads the case's own events for hashes, external addresses, domains, URLs, CVEs, techniques and command-line shapes, and matches them against stored indicators and digested reports. CTI is asked before the Investigator when there is anything to research. Interruptions rank by the specificity of the matched term, and the shift report names any agent that never spoke |
| D41 | A role may call another role while it is thinking (RFC 0012) | Asking a colleague a question went through the scheduler (post a `request`, wait for a turn, two per round) while querying eight capabilities did not, so the cheap path was the one that skipped the colleague | `Role.peers` and `ask_<role>` tools in `shoc/agents/tools.py`; a peer call runs with the peer's own principal and capability list, never the caller's. `Request`, the `domain` term lists and `roles.interested` are deleted, and the per-case ceiling `MAX_PEER_CALLS` replaces the per-round ones. The `request` and `answer` messages are still written: the openspace is the record, not the mechanism |
| D42 | No role may choose `needs_human` (RFC 0012) | Its own handling was to tell the case nobody is coming and send the crew back (D37), so it was a disposition whose meaning was "ignore this disposition" | `roles.DISPOSITIONS` has four members and `InvestigatorOutput.verdict` is typed from it; `VERDICTS` keeps the fifth because a case still reaches it without being chosen: no model, an LLM failure, citations that did not survive D25. Thin evidence is `suspicious` at low confidence, which earns a reversible containment |
| D43 | Sentinel shapes cases and has no seat (RFC 0012) | Restating findings for a reader who does not exist is formatting; deciding what a case is is work, and the case engine was doing it mechanically | It runs at intake and again when findings land on an open case, groups by shared entity, graph path and campaign, and may attach, reopen, split or re-scope. It posts no openspace message, declares no terms and cannot be asked anything. With no model the pipeline stops and findings queue, because a badly shaped case is worse than a late one |
| D44 | A finding is never dropped (RFC 0012) | Discarding noise is how a real attack dies quietly in tier one | Sentinel defers, merges or opens, and every finding stays queryable. A deferral is not a grave: deferred findings are one of the Hunter's four agenda sources, tested over a wider window, and the hunt outcome closes them |
| D45 | The Operator is deleted (RFC 0012) | Knowing that a range is the office is inventory, and it was reachable only if a scheduler called the role or one of its terms (`shared`, `production`, `deploy`) happened to appear. Those words are in every message, so it won slots on cases it had nothing to say about and was absent from the ones it did | Asset identity becomes a Surveyor lookup every role must call for an external address, host or identity. Action review becomes `BlastRadius` on every Commander proposal, cited from the Surveyor: an unanswered or uncertain count refuses the action, exactly as the Operator's refusal did. `shoc/cases/review.py` reviews with the Commander alone, and its deterministic shared-infrastructure guard is unchanged |
| D46 | The Challenger argues against the verdict, whichever it is (RFC 0012) | It only ever argued benign, so a wrong `benign_expected`, the failure nobody notices, was contested by nothing | One call per case, direction set by the verdict, grounded in a written fact, a queried baseline or a known-benign checklist and saying which. A surviving explanation must be ruled out with cited evidence, including a query that came back empty, before the case closes. When it wins on "normal here" it drafts the suppression itself, scoped to one rule and one entity with a TTL |
| D47 | Every crew role uses a model (supersedes D29, D32) | The old test split the pool by whether the answer looked mechanical, which confused the answer with the job: rule health is arithmetic, deciding which detection to write is not; source freshness is a query, deciding the SOC should stop claiming coverage is not | The Hunter, the Detection Engineer, Ops, the Surveyor and the Reporter gain prompts and schemas. Where an answer must be identical every time it is asked (the Surveyor's five questions, the Reporter's figures), it stays a query and the model sits above it. Ingest, detection, the store and the reports still work with `SHOC_LLM_PROVIDER=none`; triage no longer does |
| D48 | The Detection Engineer merges its own work (supersedes D27) | A detection nobody merges is not a detection, and a queue waiting on a human who does not open the tool is where they died | Gate, all three: fixtures pass, a backtest against real history inside a stated volume, and a filled ADS form. It narrows noisy rules and expires suppressions on its own, and reverts its own merge on noise. Silence is recorded rather than reverted, because reverting removes the coverage the rule was written for. Deleting a rule a human wrote stays a human action |
| D49 | Configuration snapshots are a connector kind (RFC 0012) | Events show what happened, so an account that exists and never acts (exactly what an attacker wants) was invisible, and every Surveyor answer carried a caveat instead | A connector may declare a snapshot pass beside log ingest: a cloud describe sweep, the IdP's users and network zones, the VCS org state, the EDR device list. The Surveyor answers from both, and the event-only caveat is removed |
| D50 | Source onboarding is its own role, the Integrator (RFC 0012) | It is the hardest thing a company with no security team does, and it was a bullet point inside a role whose job is measuring | It finishes per source: discover what is dark from what is connected, produce least-privilege scopes and the click path, then verify, sample and map alone, and it does not call a source onboarded until an event from it became a finding. It keeps that source's mapping while dormant. Order: identity, productivity, EDR, cloud, then the code host, CRM and payment provider, raised above where enterprise lists put them |
| D51 | The holder closes the case, against a deadline (RFC 0012) | Nothing closed cases once the Orchestrator was deleted, and convergence was a property of rounds | The Investigator closes when no response was needed, the IR Commander when one was. Every case carries a severity-derived deadline enforced by the scheduler: on expiry the holder is re-woken and must close or say what it is waiting for, and a second expiry pages |
| D52 | The handover becomes an exception report (RFC 0012) | There is no incoming shift and no analyst who was asleep, and a report nobody needed trains the reader to ignore the one that matters | Sent only when a decision genuinely requires a person, and carrying only those decisions. Actions taken unattended, coverage lost, cases that hit a deadline and suppressions that lapsed go in the weekly. Every figure still comes from a query, and the report is complete and sendable with no model at all |
| D53 | Every response action declares the platforms it acts on (RSP-4) | The crew offered `github.make_repo_private` for a public S3 bucket: entities are typed `resource:`, with no platform, so any resource matched the public-repository playbook | `platforms` on each action, compared with the `logsource.product` of the rules behind a case. Out of scope means blocked by policy, hidden from the Commander, and a non-matching playbook. `notify.page` has none and fits every case. The Cloudflare block left the leaked-key playbook, since it never stopped anyone calling the AWS API |
| D54 | The attack rehearsal is removed for now (AGT-7) | Not needed for now; bringing it back takes an RFC | `rehearsal.run`, `rehearsal.list`, the personas, and the weekly schedule are gone (migration 018; the `rehearsals` table stays, unread, because migrations never drop a table); migration 019 rejects the rehearsal gaps still open on the detection backlog. The Detection Engineer and the Hunter lose the rehearsal intake; coverage gaps come from CTI and the Surveyor's unwatched set. Supersedes the rehearsal half of D7, and D30 |
| D55 | A rule the Detection Engineer merges lives in `shoc.merged_rules`, per tenant (AGT-3, D48) | The image ships `content/` read-only and a tenant's merge is not another tenant's rule; a database row also leaves the revert path to the one role that made it | The loader lays merged rules over `content/` by id, so a shipped id is that rule narrowed. The gate adds a fourth test to D48: a playbook that can act on the rule's platform (RFC 0013). Fixtures run in a scratch tenant. `detection.work` runs the role daily and ends each backlog item as merged, no rule, source gap or later; `detection.decide` stays a human override |
| D56 | Every Tier 0 platform has response actions and live lookups, taken from the Splunk SOAR connectors (RSP-4, AGT-1, RFC 0014) | A Google, GitLab, Azure or GCP case could only page, and the crew could read what happened in the logs but not what is true now: which roles a user holds, which rules sit on a mailbox, who owns a key | 15 new actions and 13 lookups under `shoc/actions/`, one module per platform, chosen from each SOAR connector's contain and investigate actions and narrowed to what answers a rule we ship. `platform.lookup` reads with the action credentials, only ever issues reads, and is not offered to external agents. CI fails when a platform we ingest has no action of its own |
| D57 | shoc ships no CISA KEV feed (DET-4) | A fresh install fetched threat-intel feeds within seconds of first boot and told nobody; the maintainer chose to remove the CISA feed outright and keep abuse.ch, announced | The abuse.ch feeds stay on by default and are announced: the hosts a default install contacts are listed in the quick start and the worker names them on its first refresh. The Surveyor's "what is exploitable now", which joined against KEV, is deleted; CTI answers vulnerability relevance per case from reports it has read |
| D58 | The SOC Manager is the operator's one contact (AGT-14, RFC 0015) | Every case posted itself to Slack, every containment playbook paged, and only `unattended.py` checked whether somebody had already been woken, so one incident could reach the operator several times and the channel got muted | The Reporter becomes the Manager. Roles and playbooks hand it notices (`shoc.notices`); a query groups them by case entity and pages once per incident per day, only on a critical case, uncontainable activity, a day of dark coverage or a twice-expired deadline. The model writes the wording and a template replaces it when it cannot. `ask` goes to the Manager, which calls the crew as peers. The per-case Slack post and the 12-hour shift report are gone |
| D59 | Reports and indicators each come in three ways: a polled platform API, a polled feed URL, and one URL or value handed in (DET-4, DET-7, RFC 0016) | A vendor blog had to be pasted into `intel.digest` post by post, which only happens while somebody is at the keyboard, and a hand-held indicator had no way in | `intel_feeds` gains `parser` (`rss`, `otx_pulses`, `misp_events`, `list` join the four feeds); `intel.add` and `intel.remove` are new; an MCP external agent gets `intel:write`, its indicators capped at 0.55 confidence; `intel.configure` moves to `intel:configure` and stays human-only |
| D60 | Superseded by D65. The operator's assistant can onboard tools over MCP without approval power (API-1, SEC-1, RFC 0017) | Connecting a log source or an action credential from an assistant required `SHOC_MCP_PRINCIPAL=human`, which also lets the model approve L2 actions | `SHOC_MCP_PRINCIPAL=operator` is a human principal with the external agent's scopes plus `sources:write`, `sources:sync`, `sources:onboard`, `actions:configure` and `intel:configure`; no `actions:approve`, `actions:run` or `config:write`. External agents still get no onboarding scope |
| D61 | The audit chain is an HMAC keyed from `SHOC_MASTER_KEY`, and every change of an action's state is a row in it (SEC-1) | A plain SHA-256 chain could be rewritten and re-chained by the role that owns the table, TRUNCATE emptied it, concurrent appends could fork it, the worker, the playbook runner, the Manager and the unattended path changed action states without writing a row, and nothing checked the chain unless somebody ran `health audit` | Appends take a per-tenant advisory lock and hash `ts`; migration 025 blocks TRUNCATE, drops the `ts` default so a pre-025 process cannot append, and `shoc migrate` records the key's fingerprint and closes each older chain with a keyed `audit.checkpoint` row. A process with an empty or different key refuses to append or verify. `cases/actions.py` writes `action.proposed`, `approved`, `rejected`, `started`, `executed` and `rolled_back` under the acting principal, and `execute`/`undo` take a required `by`. The worker runs `health.audit` every hour; verification continues past a broken row, and each new break pages once under a fifth page condition, `audit_broken`. The owner can still delete the newest rows, or all of them, and the key cannot be rotated |
| D62 | Row-level security fails closed, and the suite runs as an ordinary role (amends D21; SEC-1) | D21 left a session without `shoc.tenant_id` unrestricted, and a capability pinned its tenant only when its connection was already open. Surfaces build a fresh Context on a connection the thread reuses, so a call could run unscoped or under the previous request's tenant. CI connected as the container superuser, which bypasses every policy, so no REST, MCP or worker test could see it | Migration 026: an unset or empty setting matches no row, and `shoc:all` is the only way across tenants (`shoc migrate`, `shoc grant-readonly`, the worker's queue, and psql or a backup through `SET shoc.tenant_id = 'shoc:all'`). Those set it on their connection directly; a Context refuses it, so a request naming it in `X-Shoc-Tenant` gets a 403. A Context pins the tenant when it opens its connection as well as on every call. `source.sync` loads through the writer role even for the worker's agent principal, and `events.ingest` no longer admits agents, because loading is a write (D22). CI creates the roles with `deploy/postgres-init` and runs every test as `shoc` |
| D63 | Single-user mode is for the person at this machine, and a token carries its tenant (API-1, SEC-1) | With `SHOC_TOKENS` empty every caller is a human with `*`, so an L2 approval needed only network reach, and a reverse proxy in front of loopback or a web page in the operator's browser has that reach; the Helm chart served on `0.0.0.0` that way by default, `/mcp` ignored tokens, and any token could pick a tenant with `x-shoc-tenant` | With no tokens, `shoc serve` refuses to start unless the published address (`SHOC_BIND`, else `--host`) is loopback, so Compose on loopback starts and Compose on a VPN address does not; the chart requires `SHOC_TOKENS`. An untokened request with a forwarding header, or a `Host` or `Origin` other than localhost, is refused. `/mcp`, `/metrics` and `/v1/stream` check the token like REST. A token entry takes an optional `tenant`, default `SHOC_TENANT`, and a mismatching header is refused. `SHOC_MCP_PRINCIPAL` applies to stdio only; an untokened HTTP MCP client is an external agent. `/metrics` shows one tenant |
| D64 | A scheduled detection cycle reads by ingestion time and evaluates whole event-time buckets (DET-3) | A threshold counted only the minutes since the last watermark, so a burst split across two cycles never fired. The watermark was wall-clock time compared with event time, so an event delivered late, as CloudTrail's usually are, was never evaluated. A worker down for more than four timeframes skipped the gap, and a cycle read at most 200 rows per rule | The watermark is an `ingested_at` cursor, read again 10 minutes back to cover batches that commit after they are stamped; a load that takes longer than that from mapping to commit can still be missed. A cycle lists the distinct buckets its new matches fall in and evaluates each one alone, paged by `(time, event_uid)` with no row limit, so an event with a wrong date costs one extra bucket, not the years between. A threshold fires when a timeframe-long window starting at one of the group's events holds N of them, so `count` takes only `>=` and `>`; a NULL group value is matched with `IS NULL`. Past 10,000 candidate groups in a bucket, the heaviest 10,000 are evaluated. A bucket that fails is retried once; on the second failure it is left out. Whatever a cycle leaves out is written to `rule_state.last_error` and handed to the Manager as a digest notice, and the watermark moves on. A rule that fails before its first watermark keeps the start it attempted. A backlog is read six hours of ingestion per cycle. A refreshed finding keeps the events it already cited. `--lookback` leaves the watermark alone. `rule.test`, `rule.backtest` and the Detection Engineer read at most 200 rows per scan. Indicator matching uses the same kind of watermark, kept in `rule_state` as `ioc_match`. This replaces D20's four-timeframe cap. Each rule costs one query over new rows per cycle plus one per bucket, so Postgres tenants gain an index on `ingested_at` and Databricks tables keep file statistics on it (`delta.dataSkippingStatsColumns`).
